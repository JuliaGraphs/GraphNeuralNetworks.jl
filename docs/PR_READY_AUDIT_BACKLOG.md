## Individually reproduced bugs

### AUDIT-001 — `NeighborLoader` default `input_nodes` cannot be used

**Evidence:** The keyword is declared `input_nodes::Vector{Int}=nothing` at `GNNGraphs/src/sampling.jl:36-38`, despite the following expression attempting to support `nothing`. Julia dispatch rejects the default value before the constructor body runs.

**Reproduction run:**

```julia
using GNNGraphs
g = GNNGraph([1], [2])
NeighborLoader(g; num_neighbors=[1], num_layers=1)
```

**Actual:** `MethodError: no method matching #NeighborLoader#...(::Vector{Int64}, ::Nothing, ...)`, pointing to `sampling.jl:37`. **Expected:** a loader over all graph nodes, as the constructor's own fallback indicates. Existing tests in `GNNGraphs/test/sampling.jl:86-205` always provide `input_nodes`, so they miss the advertised default.

**Minimal fix direction:** accept `nothing` in the keyword type (or remove its restrictive annotation), resolve `nodes = input_nodes === nothing ? collect(1:graph.num_nodes) : input_nodes`, and derive the default batch size from `nodes`. Regression test should instantiate with omitted `input_nodes`, iterate, and verify all nodes are covered. Risk is low if explicit `input_nodes` and explicit `batch_size` behavior stay unchanged. This is suitable as a standalone PR.

### AUDIT-002 — `sample_neighbors(..., K=0)` samples edges

**Evidence:** At `GNNGraphs/src/sampling.jl:180-185`, `K > 0 ? ... : length(eidlist[i])` treats zero like the documented `-1` sentinel. The docstring says `K=-1` means all neighbors and describes `K` as the maximum sampled count.

**Reproduction run:**

```julia
using GNNGraphs
g = GNNGraph([1, 2, 3], [2, 3, 1])
sg = sample_neighbors(g, [1], 0; dir=:out)
(g.num_edges, sg.num_edges)
```

**Actual:** `(3, 1)`. **Expected:** `sg.num_edges == 0` for `K=0`; `K=-1` should continue to select all neighbors. Existing sampling tests cover positive K and the default, but not zero. Add tests for `replace=false/true` and both directions. A tight change to distinguish `K == -1` from `K == 0` is low-risk; decide whether values below `-1` should error or retain legacy behavior.

### AUDIT-003 — empty `nodes` fails in `sample_neighbors`

**Evidence:** At `GNNGraphs/src/sampling.jl:187`, `reduce(vcat, eidlist)` has no initial value. For an empty input node collection, `eidlist` is empty and Julia throws before a graph can be returned.

**Reproduction run:**

```julia
using GNNGraphs
g = GNNGraph([1], [2])
sample_neighbors(g, Int[])
```

**Actual:** `ArgumentError: reducing over an empty collection is not allowed`, from `sampling.jl:187`. **Expected:** an empty sampled graph with stable node/edge metadata, or a clear argument validation error if empty selections are intentionally forbidden. Existing tests do not cover it. The minimal PR should establish the desired contract and test empty input with `dropnodes` both false and true. Risk centers on preserving graph feature-store dimensions and graph count for the empty result.

## Static/backend candidate needing hardware verification

### AUDIT-004 — CUDA `binarize` appears to ignore requested element type

The CUDA extension allocates `bin_vals = similar(nonzeros(Mat))`, which keeps the input nonzero element type, then fills it with `one(T)`. For Float32 input and `T=Bool`, the values remain Float32, unlike the generic implementation in `GNNGraphs/src/utils.jl:298`, which uses `ifelse` with `one(T)` and `zero(T)`. Since degree on adjacency matrices calls `binarize(A,T)` when `edge_weight=false`, an integer degree request may also retain an unintended float element type on CUDA. This is static evidence only: no CUDA device/backend was available, so keep it **Potential** until an accelerator reproduction confirms the returned `eltype` and downstream degree behavior.
